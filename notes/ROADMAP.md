## Milestone 1 — CLI & engine parity with the spec — DONE

- **`legend init <dir>`** scaffolds a fresh realm (`Nodes/`, `Landmarks/`, `.legend/taxonomy.yaml` +
  `landmarks.yaml` starters, root `AGENTS.md` per doc 06 §6.5) and indexes it immediately. Refuses
  non-empty directories. Lives in `legend_core::scaffold` so the desktop shell can reuse it.
- **`legend rename <ID> --title …`** is the only file rename path (spec §3.3 slug stability): updates
  the `title` component and re-derives the `Nodes/[ID]_[slug].md` filename; ids and bodies never change.
- **Canonicalization on write** — `write_node` resolves legacy discipline/epic/landmark aliases through
  the registries before persisting, so any CLI write leaves canonical frontmatter on disk (idempotent).
- **Harder validation surfacing** — `legend index sync` exits 1 when validation errors exist and prints
  a `fix:` suggestion per issue (declared-vs-available taxonomy branches, known landmarks, missing
  parent/dependency references, Fibonacci set, cycle links) via `Realm::suggestions_for`.
- **Round-trip guarantees** — lossless parse → render → parse tests over every node in
  `examples/realm-demo`, the four canonical doc-03 schemas, and a 400-iteration seeded property fuzz
  (`crates/legend_core/tests/roundtrip.rs`).
- **Wrap/Create ergonomics** — wrap keeps its `--title` default and per-kind body templates (doc 04
  §4.1); wrapping a Card still errors politely. Queries now filter on *computed* status so
  `query --status blocked` works (spec §6.4), and `update --status blocked` is rejected with guidance.

Acceptance: every command in design doc 06 §6.4 “Key Commands” block was run against the sample realm
and a fresh `init` realm (see verification transcript) and returns the documented behavior; 35 core
unit/integration tests green; `cargo clippy --workspace --all-targets -- -D warnings` clean.

## Milestone 2 — Desktop shell (Tauri v2)

1. **Build path**: add window icons, confirm `frontend/dist` (exists), then enable `legendary-desktop` in workspace default builds; verify a full `cargo build -p legendary-desktop` on this machine (long first compile).

## Milestone 2½ — Basic realm preview prototype (desktop + web, read-only) — DONE

A runnable slice bridging Milestone 2 (desktop shell) and Milestone 3 (read views), so a
preview of a real realm opens in the desktop app — not just a browser tab:

- Window icons: `desktop/icons/` generated by `desktop/icons/generate_icons.py` (PIL, no network);
  `bundle.icon` wired in `tauri.conf.json`. `cargo build -p legendary-desktop` verified on
  Windows (aarch64). Desktop crate stays out of workspace default-members (still needs
  `frontend/dist` + GUI deps; see AGENTS.md).
- Read-only Tauri IPC over `legend_core` (`desktop/src/ipc.rs`): `realm_open` (reloadable by
  path, returns every node + computed state + raw Markdown body in the `.legend/index.json`
  shape) and `node_body`. State kept in `tauri::State` (Mutex<Option<Realm>>). Launch
  verified end-to-end: `legendary-desktop.exe` → WebView2 → renderer → `realm_open` → 6 nodes.
- Renderer read views (`frontend/src/App.vue` + `api.ts`, `types.ts`, `lib/markdown.ts`):
  searchable, collapsible node tree (DFS rows, computed status/QP/blocked chips) + detail pane
  (component chips, meta grid, rendered Markdown body preview via a tiny dependency-free
  renderer). Selection auto-follows filter/collapse; validation errors surfaced.
- Data layer: typed client over Tauri `invoke`; plain-browser dev falls back to the checked-in
  fixture `frontend/public/realm-demo.json`, regenerated by
  `node frontend/scripts/make-demo-fixture.mjs` (`npm run fixture --prefix frontend`). Also
  regenerated `examples/realm-demo/.legend/index.json` (was stale: 5 entries vs 6 node files).
- Whole workspace `cargo clippy -- -D warnings` clean (fixed 11 pre-existing lints in
  `legend_core`/`legend_cli`); 24 engine tests + desktop ipc unit tests green; `npm run
  typecheck` + `npm run build` green.

## Milestone 3 — Renderer (Vue 3): read views first

1. **Realm data layer**: typed API client for the Tauri commands (or the CLI `--json` over a sidecar during dev), node store (reactive maps by id), computed status/landmark/QP from index payload.
2. **Tree navigator + node list** (doc 05 §5.4): discipline/epic trees from `taxonomy.yaml`; click a branch to filter nodes.
3. **Focused node workspace** (doc 05 §5.1): left markdown editor panel + metadata component editors (kind, status, priority, disciplines, epics, landmark, parent, blocked_by, quest_points, tags); all writes through the store → command → synchronous index.
4. **Card vanquish flow**: warn modal with “N active tasks … Force complete all child tasks?” before cascade (doc 04 §4.3) reusing engine counts.

## Milestone 4 — Interactive graph views

1. **Vue Flow canvas** (doc 05 §5.2): per-kind shapes (Card square, Action pill, Guard diamond, Idea dashed pill) + parent/prerequisite edges; local graph view centered on selection.
2. **Color overlay modes** `C E / C D / C P / C S` and depth-based emphasis (doc 05 §5.3), Realm Map with `[ Realm Origin ]` + 3-level completed-task visibility toggle (§5.5).
3. **Landmark Matrix** (Kanban + domain swimlanes, §5.6) and global **command palette** (`Cmd/Ctrl+K`) with graph actions & hotkeys (§5.7) — including `Ctrl+Shift+W` wrap, `Ctrl+M` reparent, `Ctrl+Enter` vanquish, `Ctrl+L` link, `Ctrl+Q` QP.
4. **Wrap/Promote & move UX**: “+ Wrap Node with Card Group” and “Move Subgraph to Parent…” controls wired to the same engine algorithms the CLI uses.

## Milestone 5 — Performance engine (Rust → Wasm)
